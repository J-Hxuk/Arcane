# ARCANE LEGACY — Codex 마법 시스템 자료 시작점

> **자료 기준:** 통합 설계 엑셀 `Arcane_Legacy_Magic_270_BossCombat_v11.xlsx`에서 데이터 추출.
> **최신 의사결정 우선:** `docs/MAGIC_SYSTEM_RULES.md` (2026-10-22 시점 대화 합의 포함).
> **프로젝트:** Godot 4.7.2 / VS Code + OpenAI Codex.
> **중요 구별:** CSV의 270종 = **설계 카탈로그**이고, 270종이 런타임에서 전부 구현되거나 영창 안정성 검증을 통과했다는 뜻이 아님.

## 1. 파일 구조

```
Arcane_Legacy_Codex_Magic_270/
├─ START_HERE.md                      # 현재 이 문서 / 읽는 순서 / 코드 감사 안내
├─ docs/
│  └─ MAGIC_SYSTEM_RULES.md           # 가장 중요한 최신 영창·속성·전투 규칙
└─ data/
   ├─ spells_270_for_codex.csv        # 권장: 전체 270종. 충돌하는 구형 전역 열 제외 + override 포함
   ├─ spells_east_150.csv             # 선택: 동양 150종만 읽기
   ├─ spells_west_120.csv             # 선택: 서양 120종만 읽기
   ├─ schools_20.csv                  # 동양 10기질 + 서양 10계열 비교
   └─ spells_270_source_v11.csv       # 원본 마스터 41열 스냅샷, 구버전 시험 문구 포함
```

CSV 인코딩은 `UTF-8 with BOM (utf-8-sig)`이고 헤더는 Codex가 파싱하기 쉽도록 영문 `snake_case`로 표기했다. 실제 주문 이름·설명·특성은 한국어/영어 병기.

## 2. Codex가 반드시 지켜야 하는 자료 우선순위

1. **현재 사용자의 최신 직접 지시·정정.**
2. `docs/MAGIC_SYSTEM_RULES.md`의 `[확정]` / 최신 채택 방향. 이 문서가 v11의 **오래된 실험 문구보다 우선**.
3. `data/spells_270_for_codex.csv`의 개별 주문 설명, 별도로 명시된 `current_rule_override`.
4. `data/spells_270_source_v11.csv`: 원본 데이터 감사·추적용. 전역 시전 규칙의 자동 구현 근거로 삼지 말 것.
5. 과거 엑셀·메모 등 역사 자료.
6. **구현 사실**은 언제나 현재 저장소의 실제 소스 코드/빌드/테스트를 우선한다. 기획 확정을 구현 완료로 판정하지 않는다.

## 3. 원본 엑셀 v1.1에서 폐기·정정된 사항

| 구버전 열/설계 | 최신 우선 적용 규칙 |
|---|---|
| `legacy_focus_and_hold_notes`의 '안정화 20% 감소' | **폐기.** 영창 후 강제 안정화 대기시간은 없음. 마나의 **구조 안정성 계산**과 대기 시간을 혼동 금지. |
| 초집중 이동속도 70% 등 | **폐기.** Shift 더블탭으로 초집중, **이동 불가**. 자동 영창/무적 없음. 구체 보너스 수치는 미정. |
| 모래 적중 **10스택 → 강제 다운 그로기** | **폐기.** 실제 모래 피해량에 비례하는 독립 마모 게이지. 임계 시 **심한 이동 둔화 + 받는 피해 증가**. 공격 모션/차징을 무조건 끊지 않음. 계수/면역 시간은 시험값 미확정. |
| 경량/표준/중량을 영창 첫 키부터 알려 주는 식의 분류 | 불가. 시전 위험은 입력을 마친 뒤 발현 구조로 판단. 사전 고정 정답 속성의 신호처럼 노출하지 말 것. |
| 고위일수록 고정 추가 대기시간 | 불가. 1~5개 조작어 직접 입력 시간 자체가 중요. 크고 강력한 마법에는 전후딜/위험을 별도 검증하되 안정화 대기 추가 금지. |
| 보스 사용 타이밍 270개에 서로 다른 정답 창 배정 | 불필요. 짧은 틈 → 단순 마법/마나·물약 관리, 큰 틈 → 4~5영창/초집중/HOLD가 기본. |

**주의:** 깨끗한 CSV에도 `status_effects_and_boss_limits`, `derived_effects_and_tradeoffs` 등은 과거 설계 수치가 남을 수 있다. `current_rule_override`와 최신 MD를 우선 적용하고, 수치가 다른 경우 **불일치 보고 + 사용자 확정 요청**을 거쳐야 하며 임의로 마이그레이션하지 않는다.

## 4. 현재 프로젝트와 270종 기획의 관계

- Codex의 2026-10-20 보고상 **정식 F5 등록 28종 (그 중 물 15종)**. 이것은 **보고 당시**의 상태이며 실제 현재 프로젝트를 열어 재검증해야 한다.
- 개인 12개 조작어 대응표, 최대5 입력, 반복 허용, 주문 ID는 조작어 **Multiset**과 활성 계열로 결정.
- 실제 입력 **순서**는 B+O+T/raw 잔차를 통해 연속 물성·비용·VFX에 영향을 줌. 특정 키순서만 고유 주문·특수효과를 만든다고 하드코딩 금지.
- 영창은 전부 수동. 초집중은 Shift ×2 이동 불가. 광선·분사는 **완료 후 LMB HOLD, 키업 즉시 종료**가 기본 방향.
- 실시간 마나 관측: 일반 월드는 마나 흐름의 직관적 VFX, 연구실은 구조/축/입력 단계별 진단.
- 지팡이는 **저위력 접촉·중독/표식 등의 반응 트리거**. 일반 자동 MP 수급 수단이 아님. 포션을 포함한 전체 마나 예산은 밸런스 대상으로 둔다.
- 동양 = 오행 × 음양 10계열, 150종 제안. 서양 = 4원소 + 서로 다른 두 원소 융합 6계열, 120종 제안. 만류귀종: 동일 현상·피해 판정을 재사용 가능.

## 5. 설계 데이터 해석

- `design_mp`, `design_direct_damage`: **설계 시험 수치**. `godot_*_reported`가 있더라도 해당 보고 시점 값일 뿐; **현재 소스와 재대조**.
- `legacy_spell_id`: 구 오행 주문과의 계보. **기존 OH-ID, 실제 저장, 개인 키맵은 임의 삭제/재배정 금지**.
- `chant_multiset`: 키의 **기호(조작어 명칭) 다중집합**, 특정 캐릭터의 알파벳 키가 아님.
- `focus_order_example`, `spread_order_example`: 같은 주문 내부 물성 순서 실험의 **예시**. 자동 시전 레시피 또는 고정 유일 정답이 아님.
- `design_approval_status`, `design_test_status`, `runtime_stability_verification`: 설계 제안/미검증은 구현 완료가 아니다.
- `current_rule_override`: 일부 계열에 적용되는 최신 정책 정정. 빈 칸이어도 `MAGIC_SYSTEM_RULES.md`의 전역 규칙은 모두 적용.
- `spells_270_source_v11.csv`은 기존 엑셀의 원본 41열을 보존한 것이므로 **구형 충돌 자료도 포함**한다. 자동 코드 생성의 1차 소스로 사용하지 말 것.

## 6. 첫 Codex 작업은 '코드 감사'부터

**지금은 270종을 한 번에 구현하거나 기존 저장값을 변경하지 말 것.**

1. 실제 Godot 프로젝트를 읽어 현재 영창 계산·연구·마나탈진·F2 QA·F5 등록 상태와 CSV/MD의 차이를 코드 경로/함수명으로 확인.
2. 기존 구현값을 동양/서양 새 체계의 기획값으로 **자동 덮어쓰기 금지**. 충돌 표 생성.
3. 데이터 모델은 World/Region, Element, Nature(Yin/Yang) or Fusion, Multiset, actual permutation, spell behavior, status/VFX tags 등을 분리.
4. 기존 정식 주문/저장/개인 조작어 키맵을 보존하는 마이그레이션 설계.
5. 공통 전투 엔진(틱/HOLD, 표식·독·지팡이 트리거, 독립 마모, 연막 LOS)의 의존성과 테스트 우선순위 분류.
6. 우선 대표 주문 8~10개로 작은 틈/큰 틈 전투 루프 검증. 실제 세계관·정식 보스에 의존하지 않는 F2 임시 테스트 활용.
7. **코드 수정 전에** 감사 보고서를 제시해 사용자 검토를 받을 것.

## 7. 후속 수정 방법

원본 권위 데이터는 통합 엑셀 v11(과거 스냅샷)이지만, 대화에서 확정한 새로운 전투 규칙은 `docs/MAGIC_SYSTEM_RULES.md`에 반영되어 있다. 주문 수치 및 행을 수정할 때는 **어느 파일을 최종 단일 기준으로 삼을지** 결정하고, 동일 주문 ID/수치의 파일 간 불일치를 검사하라. 이 CSV만 편집하고 원본 엑셀을 최신으로 간주하면 안 된다.
